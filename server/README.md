# שרת ההתחברות (Auth Server)

שרת קטן ועצמאי שאחראי על התחברות משתמשים, ניהול הרשאות, ואישור העלאות קבצים.
הוא לא מאחסן את נתוני המחירון/ספקים של האתר עצמם (אלה עדיין נשמרים בדפדפן
כמו קודם) - תפקידו הוא לומר לאתר "מי מחובר ומה מותר לו", ולוודא שקובץ לא
מתחיל להיקרא בדפדפן לפני שהשרת אישר שלמעלה יש הרשאה בפועל.

## הרצה

```
cd server
npm install
cp .env.example .env
# ערכו את .env: שנו את JWT_SECRET ואת סיסמת המנהל הראשונית
npm start
```

השרת עולה כברירת מחדל על פורט 4000 (`PORT` ב-`.env`).

בהפעלה הראשונה, אם אין עדיין אף משתמש, נוצר אוטומטית משתמש מנהל (`admin` /
הסיסמה מתוך `ADMIN_PASSWORD`). יש להתחבר איתו ולשנות סיסמה / ליצור משתמשים
נוספים מיד עם ההרצה הראשונה.

## חיבור לאתר (Frontend)

באתר (בתיקיית השורש של הפרויקט, לא בתיקיית `server`) יש להגדיר את הכתובת של
שרת זה במשתנה הסביבה `VITE_API_URL` (למשל בקובץ `.env`):

```
VITE_API_URL=https://auth.your-domain.co.il
```

בפיתוח מקומי אפשר להשאיר `VITE_API_URL=http://localhost:4000`.

## תפקידים (Roles)

- `viewer` - מחובר, אך ללא הרשאת העלאת קבצים (ברירת מחדל למשתמש חדש).
- `uploader` - יכול להעלות קבצי Excel/PDF באתר.
- `admin` - יכול להעלות קבצים וגם לנהל משתמשים (יצירה/מחיקה/שינוי תפקיד) דרך
  מסך "ניהול משתמשים" באתר.

ניהול המשתמשים כולו נעשה דרך מסך הניהול באתר (זמין רק למחוברים כ-`admin`) -
אין צורך לגעת בקבצים בשרת לאחר ההתקנה הראשונית.

## אכיפת העלאות (Uploads)

כל קובץ שמשתמש מעלה באתר (Excel במחירון, Excel בספקים, צרופות/PDF) נשלח
קודם לנקודת הקצה `POST /api/uploads` בשרת הזה, עם טוקן ההתחברות של המשתמש.
השרת בודק שהמשתמש מחובר ושיש לו תפקיד `uploader` או `admin` **לפני** שהדפדפן
ממשיך לקרוא ולעבד את הקובץ - כך שגם עקיפה של הממשק (למשל דרך כלי מפתחים
בדפדפן) לא עוזרת: בלי טוקן תקין עם הרשאה, השרת מחזיר שגיאה והעיבוד לא קורה.

כל העלאה שמאושרת נשמרת כקובץ בתיקיית `uploads/` ונרשמת ביומן (`data/uploads.json`)
עם שם המעלה, סוג הקובץ, גודלו והזמן. מנהלים יכולים לצפות ביומן הזה דרך
"יומן העלאות" באתר.

## פריסה בפועל

זהו שרת Node.js/Express רגיל שלא תלוי בבסיס נתונים חיצוני (משתמשי המערכת
ויומן ההעלאות נשמרים בקבצי JSON בתיקיית `data/`, עם סיסמאות מוצפנות בלבד -
`bcrypt`). ניתן להריץ אותו עם `pm2`, כשירות `systemd`, בתוך קונטיינר Docker,
או בכל דרך אחרת שנהוגה בחברה להרצת שירותי Node - כל עוד תיקיות `data/`
ו-`uploads/` נשמרות בין הפעלות (כדי לא לאבד את רשימת המשתמשים והיומן)
והשרת נגיש מהכתובת שמוגדרת ב-`VITE_API_URL`.
