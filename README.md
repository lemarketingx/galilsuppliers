## התחברות והרשאות

לאתר יש מסך התחברות (שם משתמש + סיסמה). למשתמשים יש שלושה תפקידים אפשריים:
- **צפייה בלבד** - לא רואה בכלל את אפשרויות העלאת הקבצים.
- **מורשה העלאה** - יכול להעלות Excel/PDF.
- **מנהל מערכת** - כמו מורשה העלאה, וגם יכול לנהל משתמשים (מסך "ניהול
  משתמשים": הוספה, מחיקה, שינוי תפקיד, טיפול בבקשות "שכחתי סיסמה").

ה-API שמטפל בזה (`/api/...`) הוא Vercel Serverless Function אחד (`api/index.js`,
עוטף אפליקציית Express מ-`lib/app.js`) שרץ **באותה פריסה בדיוק** כמו האתר עצמו -
אין צורך בשרת נפרד, בדומיין נפרד או בהגדרת VITE_API_URL.

### פריסה ב-Vercel

1. Upload / Import project, כרגיל. Build command: `npm run build`, Output: `dist`.
2. בפרויקט ב-Vercel: **Storage → Create Database → KV** (מבוסס Upstash Redis,
   יש שכבה חינמית). לאחר החיבור, Vercel מוסיף אוטומטית את משתני הסביבה
   `KV_REST_API_URL` / `KV_REST_API_TOKEN` לפרויקט - זה מה שמאפשר לרשימת
   המשתמשים ולהרשאות "לזכור" בין בקשה לבקשה (בניגוד לדיסק המקומי, ש-Vercel
   מוחק בכל קריאה).
3. **Settings → Environment Variables**, הוסיפו:
   - `JWT_SECRET` - מחרוזת אקראית וארוכה (ראו `.env.example` להסבר איך ליצור).
   - `JWT_EXPIRES_IN` - למשל `12h`.
   - `ADMIN_USERNAME` / `ADMIN_PASSWORD` - נוצרים אוטומטית כמשתמש הראשון
     בהפעלה הראשונה, אם עדיין אין אף משתמש. שנו את הסיסמה מיד אחרי ההתחברות
     הראשונה (ניתן אז גם להסיר את שני המשתנים האלה).
4. Redeploy (כל שינוי במשתני סביבה דורש דיפלוי מחדש כדי להיכנס לתוקף).

### הרצה מקומית

```
npm install
cp .env.example .env    # ומלאו JWT_SECRET משלכם
npm run dev:api         # מריץ את ה-API על פורט 4000
npm run dev              # בטרמינל נפרד: האתר עצמו, עם פרוקסי אוטומטי ל-/api
```

בלי `KV_REST_API_URL`/`KV_REST_API_TOKEN` (לא מוגדרים בברירת מחדל בפיתוח
מקומי), ה-API נופל אוטומטית לאחסון מקומי בקבצי JSON תחת `.local-data/`
(לא נשמר בגיט) - כך שהכול עובד מקומית בלי לחבר KV אמיתי, אבל **בפריסה
בפועל ב-Vercel חובה לחבר KV** אחרת נתוני המשתמשים לא נשמרים בין בקשה
לבקשה.
